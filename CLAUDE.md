# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A Super Nintendo (SNES) homebrew platformer written in C, built with **PVSnesLib** (a C SDK for the SNES built on the `tcc816` compiler and the `wla-65816`/`wlalink` toolchain). Target platform: LoROM, SlowROM, 8 ROM banks. Output is a `.sfc` ROM run in the **Mesen** emulator.

The vendored SDK and emulator live under `tools/` (`tools/pvsneslib/`, `tools/mesen/Mesen.exe`) and are third-party — do not edit files under `tools/`.

## Environment setup

Build tooling is not on PATH by default. Two ways this is provided:

- **One-time (persistent)**: `powershell -File tools/setup_env.ps1` sets the `PVSNESLIB_HOME` / `DEVKITSNES` user env vars and adds `tools/pvsneslib/devkitsnes/bin` and `C:\msys64\usr\bin` to the user PATH.
- **Per-run (session-local)**: `run.bat` sets `PVSNESLIB_HOME`, `DEVKITSNES`, and `PATH` inline before building — this is what to use if the persistent env vars haven't been set up.

The build requires MSYS2 (`C:\msys64`) for `make` and other POSIX tools, plus the SDK binaries in `tools/pvsneslib/devkitsnes/bin/` (`816-tcc.exe`, `wla-65816.exe`, `wla-spc700.exe`, `wlalink.exe`).

## Common commands

Build and run (compiles, then launches the ROM in Mesen):
```
run.bat
```

Build only, from an MSYS2 bash shell with `PVSNESLIB_HOME` exported:
```
make
```

Clean build artifacts, ROM, and graphics/audio conversion outputs:
```
make clean
```

Build only, from PowerShell (what Claude Code should use — the sandboxed Git Bash tool cannot run `wla-65816`, which writes a temp file to the drive root):
```
$env:PVSNESLIB_HOME="/e/ProyectoSNES/tools/pvsneslib"; $env:PATH="E:\ProyectoSNES\tools\pvsneslib\devkitsnes\bin;C:\msys64\usr\bin;"+$env:PATH; make
```

The equivalent VS Code tasks (`.vscode/tasks.json`) run these same `make` invocations through `C:\msys64\usr\bin\bash.exe`: **"Build SNES ROM"** (default build task) and **"Clean Project"**.

There is no test suite or linter in this project.

## Architecture

- `src/main.c` — the entire game currently lives here as a single `main()`. It initializes the SNES via `pvsneslib` calls (`consoleInitDefaultText`, `bgSetGfxPtr`/`bgSetMapPtr`, `setMode`, `setScreenOn`), then loops on `WaitForVBlank()` for 60 FPS timing. New game code should build on this loop structure.
- `Makefile` — declares `ROMNAME`/`ROMTITLE` and includes the SDK's shared build rules from `${PVSNESLIB_HOME}/devkitsnes/snes_rules`, which define the actual compile/link/graphics-conversion pipeline (`.c` → `.ps` → `.asm` → `.obj` → `.sfc`, plus `.pic`/`.brr` asset conversion rules). Project-specific build behavior is configured by overriding Makefile variables, not by editing `snes_rules`.
- `hdr.asm` — **auto-generated** by `snes_rules` from the Makefile's `ROMNAME`/`ROMTITLE`/ROM-mode variables on every `make`. It defines the SNES memory map, ROM header, and interrupt vector table (NMI → `VBlank`, RESET → `tcc__start`). Do not hand-edit; if custom vectors/memory map are needed, set `AUTOHDR := 0` in the Makefile and ship a hand-written `hdr.asm` instead.
- `linkfile` — lists the object files passed to `wlalink` to produce the ROM: `src/main.obj`, `hdr.obj`, and the PVSnesLib runtime/libc/libm objects from `tools/pvsneslib/pvsneslib/lib/LoROM_SlowROM/`. Regenerated by the build; reflects the LoROM/SlowROM target.
- Build outputs at the repo root (`ProyectoSNES.sfc`, `.sym`, `.symfull`, `*.obj`, `ProyectoSNES.log`) are generated artifacts, not source.
- `.vscode/c_cpp_properties.json` points IntelliSense at the `tcc816` compiler and the PVSnesLib `include/` path for correct SNES-specific header resolution (e.g. `snes.h`).
